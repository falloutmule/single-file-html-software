# Authority and boundaries

Apply sources in this order: explicit current user authorization; current repository contracts, `AGENTS.md`, and selected plugin skill; this One-Shot instruction set; selected-lane guidance; project packet/assets; templates/examples; historical reports.

SFHS core owns project/artifact/evidence contracts, adapters, lifecycle, viewport primitives, CLI, packing, verification, browser execution, release gates, and diagnostics. One-Shot owns intake, sequencing, prompts, packets, issue/decision tracking, acceptance framing, recovery, and evaluations. Projects own mechanics, physics, art, controls, levels, assets, and project-specific scenarios.

Never introduce a second adapter, loop, packer, verifier, browser runner, evidence system, or release system. Never allow a historical game/report to override current repository truth.
