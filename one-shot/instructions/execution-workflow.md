# Authorized execution workflow

Classify first: `DISCUSSION`, `PLAN`, `IMPLEMENT`, `REPAIR`, `INTAKE`, or `VERIFY`. Do not edit or create artifacts for discussion or planning.

For authorized implementation, capture brief, authorized scope, decisions, issues, acceptance criteria, and intake status before source work. Start with the central verb and highest-risk interaction; expand only after it works. Continue autonomously through the authorized boundary and record meaningful failures as they occur.

Use current commands in this order: `inspect`, `validate`, changed-path `check`, `pack`, `verify`, then appropriate browser evidence. Treat a physical-device verdict as a separate acceptance gate. Return for a required product decision, unavailable authority, or external-only blocker—not routine phase review.
