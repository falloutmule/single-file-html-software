# Player-visible acceptance

Write acceptance criteria in player-observable terms: what must be visible, understandable, controllable, and stable. Coordinates, object existence, DOM inspection, or a source test alone do not prove the mechanic is visible.

For visual repair, reproduce the visible defect, capture the player-facing invariant and evidence state, then repair the visible path. Mark earlier contrary automated proof `SUPERSEDED`; do not preserve an overclaim merely because an internal proxy passes.
